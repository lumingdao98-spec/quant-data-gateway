# V3.26 三面决策、评分与交易闭环审计

## 1. 结论

系统的自动交易执行分统一由 `SignalFusionEngine.final_score` 产生。筛选综合分只作审计对照，不再和筛选分项重复计权。技术面、信息面、资金面以及大盘环境必须同时记录数据源、时点、质量、缺失和是否允许自动入场。

当前完成度：

| 模块 | 完成度 | 可用于什么 | 仍有限制 |
| --- | ---: | --- | --- |
| 技术面 | 8/10 | 日K结构、分时择时、量价、异常和止损止盈 | 指标是价格变换，不代表预测胜率 |
| 信息面 | 7/10 | 公告/新闻去重、正文质量、未来事件提醒、重大负面否决 | 部分来源仍只有标题；历史PIT覆盖不足 |
| 资金面 | 6/10 | 成交额、量比、VWAP、盘口承接、公开板块资金流 | 没有Level-2时不能声称识别主力账户或虚假撤单事实 |
| 大盘情绪 | 7/10 | 上证、深成指、创业板、沪深300、科创50与市场宽度 | 指数/宽度证据不足时必须排除，不允许用小自选池代表全市场 |
| 回测闭环 | 7/10 | 历史K线、资金管理、止损止盈、订单成交、图表标注 | 单票快速回测没有历史信息/资金PIT库，当前只用技术/量价 |
| 实时模拟 | 8/10 | 最新缓存、统一执行分、三面门禁、风险、模拟成交、持仓、审计 | 公开数据延迟和缺失仍会阻断自动入场 |
| 真实交易 | 7/10 | 预检查、确认队列、BrokerAdapter、kill switch、审计 | QMT/PTrade需本机SDK、授权和用户配置，默认关闭 |

## 2. 唯一执行分

默认目标权重：

| 维度 | 权重 | 作用 |
| --- | ---: | --- |
| 技术面 | 30% | 日K结构55% + 当日分时45%，决定趋势和择时 |
| 基本面 | 22% | 公司质量、估值和长期适配 |
| 信息面 | 20% | 近期公告/新闻、预期差和重大负面 |
| 资金面 | 16% | 量价承接、公开资金流和盘口可用证据 |
| 大盘情绪 | 12% | 市场环境调分和弱势降仓 |
| 筛选总分 | 0% | 仅审计；所有分项都缺失时才作低置信兜底 |

公式：

```text
执行分 = Σ(有效分项分 × 有效权重归一值) - min(异常分 × 0.35, 35)
```

规则：

1. 分数必须是有限数且位于0到100；否则作为无效数据排除。
2. 缺失分不补50分；剩余有效权重重新归一化到100%。
3. 筛选综合分不与筛选分项同时计权，避免技术/信息/资金重复计票。
4. 大盘分低于40时降低目标仓位，不直接制造买入信号。
5. 信息重大负面、异常阻断、技术破位、数据过期可覆盖分数结论。
6. 评分达到阈值只是候选动作，仍必须通过三面就绪、数据新鲜度和风险网关。
7. 有原始分但质量状态为 `unusable`、`missing`、`stale` 或证据不足时，原值只留在审计快照，进入执行融合器的值必须为缺失；不能先计权、再仅靠末端门禁掩盖。

权重不是固定真理。默认值用于波段/混合策略，策略族可以改变“必需维度”和仓位，但不能跳过真实性门禁：

| 策略族 | 必需维度 | 说明 |
| --- | --- | --- |
| 短线/事件驱动 | 技术、信息、资金 | 盘中信息或承接缺失时禁止新增仓位 |
| 长线/核心卫星 | 技术、信息 | 更重公司和事件，不用小止盈止损替代长期退出逻辑 |
| ETF/定投 | 技术、资金 | 不按个股基本面硬打分，极端风险时暂停 |
| 通用混合 | 技术、信息、资金 | 缺任一必需维度只观察或提醒 |

## 3. 大盘情绪

大盘总分采用指数趋势和市场宽度：

```text
大盘分 = 70% × 可用指数趋势加权 + 30% × 市场宽度
```

指数目标权重：上证25%、深成指20%、创业板25%、沪深300 20%、科创50 10%。缺失指数按可用权重重算，但至少需要两类独立证据（多个指数，或指数加有效宽度）；单一指数加少量自选股不允许进入自动评分。

市场宽度少于20只为无效样本；20到79只只表示有限范围；80只以上才接近较宽市场样本。宽度样本必须明确说明范围，不能把当前候选池标成全市场。

## 4. 三面数据边界

### 技术面

- 输入：真实日K、分钟/分时、成交量、成交额、复权口径和数据时间。
- 输出：均线、MACD、KDJ、RSI、BOLL、ATR、支撑压力、日K分和分时分。
- 自动交易：用于方向、时点、止损距离和异常识别。
- 失效条件：K线不足、跨日分时、过期行情、非有限值、异常复权混用。

### 信息面

- 优先级：交易所/巨潮/官方公告 > 财报和公司正式披露 > 主流财经媒体 > 社区情绪。
- 同一事件按事件键去重；转载只增加来源验证，不重复加分。
- 正文、结构化摘要、标题级证据分别计质量；模板页、搜索结果页和无正文内容不计方向分。
- 中报、财报披露、交割日和已公布会议进入未来事件日历。规则推算但未公开确认的日期只提醒，不计多空分。
- 重大负面可以否决买入；低质量或过期信息只能用于观察/提醒。

### 资金面

- 公开资金流存在时用于相对强弱和板块轮动。
- 没有逐笔或Level-2时，仅使用成交额、量比、VWAP、分时量价和盘口快照作为代理。
- 代理数据可以描述“承接偏强/偏弱”，不能描述为“主力净流入”“吸筹事实”或“确认虚假撤单”。
- 虚假撤单只能在连续盘口快照能够复核挂单出现、撤销、停留时间和成交结果时输出风险提示。

## 5. 四种使用方式

### 筛选

筛选页负责建立股票池和分项底座，输出分项、适配策略、风险、缺失数据和快照ID。没有筛选分项的纯代码配置只能进入观察池，目标仓位为0。

### 回测

回测只能使用 `decision_time` 当时可得的数据。当前单票快速入口只有历史K线，因此实际评分权重为技术/量价100%；基本面、信息面、资金面和大盘只展示实时目标权重，不参与历史成交。建设完整三面历史回测必须先建立带 `available_at` 的PIT快照库。

### 实时模拟

筛选分项作为底座，实时日K/分时更新技术分，近期信息和资金证据更新各自分项。执行分、三面门禁、风控、订单、成交、持仓、账户和标注共用一个会话并落SQLite。休市只待机；手动回放必须明确标记，不混成盘中成交。

### 实盘与提醒

实盘复用模拟交易的决策快照，不重新另算一套分。买入必须同时满足数据新鲜、三面就绪、评分溯源、风险通过、人工确认、券商连接、白名单、金额/次数上限和非kill状态。

实时模拟、实盘预检查和同花顺提醒读取同一个 `dimension_readiness`。任何未就绪分项在前端显示“未参与”，在评分明细保留原始值和剔除原因，在执行分中不占权重。

同花顺伴侣只负责启动客户端和生成待人工确认票据；没有验证的官方委托API时，不声称已报单或成交。

## 6. 开源架构对照

- [TradingAgents](https://github.com/TauricResearch/TradingAgents)：借鉴分析角色、交易判断、风险复核和组合经理审批的分层，不把LLM文本直接当订单。
- [vn.py](https://github.com/vnpy/vnpy)：借鉴数据、策略、账户、执行和网关解耦，以及事件驱动状态更新。
- [Qlib](https://github.com/microsoft/qlib)：借鉴数据集、模型、策略、回测和分析边界，强调可复现和时点一致性。
- [RQAlpha](https://github.com/ricequant/rqalpha)：借鉴账户、撮合、费用、交易日历、风控和分析器的模块化。

当前系统的对应链路是：

```text
真实数据/缓存
  -> RealtimeDecisionService
  -> DecisionDimensionService
  -> SignalFusionEngine (唯一执行分)
  -> RiskGateway
  -> OrderManager / ExecutionRouter
  -> Paper 或 BrokerAdapter
  -> PortfolioAccounting / TradingStore / ChartMarker
```

## 7. 后续优先级

1. 建立历史基本面、公告、板块资金和大盘快照PIT库，再开放真正的五维历史回测。
2. 增加全市场宽度和指数缓存的后台刷新，避免筛选时同步请求多个外部源。
3. 为公开板块资金流建立分钟/日级历史，支持上午、下午和近5/20日轮动对比。
4. 增加数据源契约监控：字段覆盖率、延迟、错误率、内容质量和连续缺失告警。
5. AI只读取同一决策快照做解释和反方审阅，输出必须落审计，不能绕过规则风控直接下单。
# V3.26 评分权重与执行口径复核

## 当前唯一执行分

`SignalFusionEngine.final_score` 是回测复盘之外，实时模拟、实盘预检查和同花顺委托提醒共同引用的唯一执行分。筛选总分只负责候选排序和审计，不再和已经拆出的基本面、技术面、信息面、资金面重复计权。

默认目标权重为：基本面 22%、技术面 30%、近期信息 20%、资金面 16%、大盘情绪 12%。技术面权重最高，因为它承担日K结构和分时择时；资金面只给 16%，因为公开免费源很多时候只是量价/公开资金流代理，不能冒充 Level-2 主力账户；大盘情绪只占 12%，避免指数涨跌替代个股判断。

这些是目标权重，不是对缺失数据强行补齐。某一维缺失、过期、质量不足或不在 0-100 范围时，该维度被剔除，剩余有效权重重新归一化。例如只有技术面和资金面可用时，实际权重为 `30/(30+16)` 与 `16/(30+16)`。自动新增仓位仍受策略必需维度门禁约束，不能因为重新归一化就绕过缺失信息。

异常/行为风险不作为第六个正向维度，而是在风险前得分之后单独扣减，最高扣 35 分。默认阈值：62 分进入买入观察，72 分允许加仓候选，45 分以下减仓或卖出；最终还必须经过数据新鲜度、交易时段、仓位、止损止盈、日亏损、重复订单、人工确认和券商状态门禁。

## 大盘情绪复核

大盘情绪只使用可追溯指数趋势和有效市场宽度。指数样本或宽度无效时，不再把“中性 50”混进总分；至少需要两个有效证据单元才允许计分。板块资金流与主线强度作为市场事件和个股行业暴露的辅助证据展示，不直接伪装成指数情绪，也不把公开资金代理表述为主力真实账户。

## 无效数据处理

- 没有近期可核验正文、公告或结构化事件时，信息分为 `None/缺失`，不再显示成有效 50 分。
- 有明确来源、可用时间和个股作用域的结构化 PIT 事件，可从中性基线计算事件影响；规则推算的未来会议、中报窗口和交割日只提醒，不提前计入方向分。
- 没有基本面来源和披露/可用时间时，基本面分即使数值存在也不参与自动交易。
- 实时模拟和实盘使用落库时的 `dimension_readiness`，解释页不再根据不完整摘要二次猜测。
- 实盘和同花顺人工委托提醒默认只接受 300 秒内评分溯源；过期评分保留复盘，但不能生成可执行提醒。
