# V3.21 Backtest Gap Audit

本轮目标是把历史回测、筛选评分和盘中模拟交易拆清楚，并形成“信号 -> 仓位 -> 订单 -> 风控 -> 模拟成交 -> 持仓 -> 复盘报告”的研究闭环。系统仍然不连接真实券商，不真实下单。

## Legacy 单票回测与新版组合回测

- `quant_data/services/backtest_service.py` 是 legacy 单票快速验证，适合检查某个标的的 K 线、买卖点和指标展示。
- `quant_data/backtest/engine.py` / `BacktestEngineV320` 是科学回测入口，使用信号日和下一交易日成交、A 股 T+1、手数、涨跌停、滑点和费用约束。
- `/backtest` 页面为了保留图表体验仍可用 legacy 参数，但接口和页面都必须显示“研究辅助，不构成投资建议”。

## 当前不足

- 仓位控制原先主要依赖固定仓位，不能区分评分加权、波动率目标、ATR 风险、定投、金字塔加仓和核心-卫星。
- 收益再投资口径不够显式，页面未清楚区分初始资金、现金、持仓市值、总权益、可用资金和再投资资金。
- 短线、中线、长线、定投共用一套买卖阈值，不能按持仓周期切换止损、持仓天数、风险过滤和仓位纪律。
- 当前历史回测不能把当日公告、新闻、财务和大盘环境完整 point-in-time 回填；没有历史数据时只能用于实时观察或从当前时点开始模拟。
- 盘中模拟此前只有 paper broker 雏形，缺少实时信号流、异常波动规避、风控网关、订单状态、持仓和审计日志闭环。
- 技术面、基本面、信息面和大盘情绪原先没有统一信号对象；缺失数据容易被误当作 0 分。
- 异常波动、数据过期、信息面重大负面和行情源异常需要在下单前阻断。

## V3.21 修复闭环

- 新增 `PositionSizer` 和 `MoneyManager`，支持多仓位模式、复利/不复利、资金流水和亏损降仓。
- 新增 `StrategyHorizonConfig`，把盘中、短线、中线、长线、定投和混合策略规则分开。
- 新增 `SignalFusionEngine`，按基本面、技术面、信息面和市场环境动态归一化合成 `UnifiedSignal`。
- 新增 `AnomalyGuard` 与 `DataFreshnessGuard`，异常波动和 stale 数据在订单前降权、阻断或要求人工确认。
- 完善 `RiskGateway`，在 paper/live 订单前统一检查仓位、现金、ST/黑名单、交易时段、涨跌停、低流动性、日内亏损和人工确认。
- 新增 `PaperAccount`、`OrderManager` 和 `RealtimePaperEngine`，实现 paper-only 的信号、订单、成交、持仓和审计日志。
- 新增 `/realtime-paper` 页面和 API，支持从筛选结果加入实时模拟池、手动 tick、分时回放和状态查看。

## 仍不能用于真实下单

- 没有接真实券商、真实委托、撤单、成交回报、资金股份同步。
- 五档盘口依赖公开源，缺失时只显示委比/委差和缺失原因，不伪造 Level-2。
- 历史信息面和大盘环境缺少完整 point-in-time 数据时，不允许把当前信息回填到历史。
- 自动交易前仍需至少完成连续 paper 运行、真实盘口对照、人工确认队列、权限隔离和审计留痕。
