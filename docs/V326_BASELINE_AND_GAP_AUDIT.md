## 实际信息抽查

2026-08-24 对阳光电源 `300274` 做了两轮真实公开来源刷新，并直接检查 `data/news_cache.json` 和 SQLite 信息库中的标题、正文、链接、附件、发布时间和事件时间。

发现的问题：

1. 旧缓存中的部分 `summary` 不是新闻正文，而是东方财富页面导航和免责声明；这类文本不能作为利多利空证据。
2. 公开公告标题和链接大多真实，但“有标题”不代表“已取得正文”。正文缺失时不应给出完整事件判断。
3. 旧版近似标题去重会把不同日期的担保进展公告合并，也会把同日不同候选人的声明合并，导致事件链断裂。
4. 未来会议、财报窗口和衍生品交割观察日期没有从当前信息分中分离，容易把“未来可能发生”误解为“结果已经发生”。
5. 旧页面只显示总条目数，无法区分正文已核验、结构化摘要、仅标题和网页壳。

真实正文验证示例：东方财富公开公告内容接口能够返回阳光电源首次回购的股份数、占比、成交价格、金额和 PDF 附件；它与公告 HTML 壳是两个不同的数据质量等级。

## V3.26 已实施规则

### 正文真实性

- 优先读取公开公告内容接口和公开 PDF 链接。
- 页面导航、菜单、免责声明和脚本片段标记为 `boilerplate_rejected`，从当前评分中排除。
- 每条信息记录 `content_source`、`content_quality_status`、`content_missing_reason` 和 `content_hash`。
- 内容等级为：`full_text`、`structured_excerpt`、`title_only`、`boilerplate_rejected`。

### 去重与事件链

- 相同文档编号、相同正文哈希或相同 URL 才直接合并。
- 跨来源且同日、标题完全一致的公告可视为转载。
- 相同明确事件日期和相同会议类型可合并多源报道。
- 不同日期的进展公告保留为独立事件。
- 同日但不同文档编号、不同人员或不同议案的官方文件保持独立。
- 合并后保留来源、原文链接、附件和重复数量；同一事件只进入评分一次。

### 未来事项

- 从已取得正文中重新提取股东大会、董事会、披露、登记、解禁、交割、到期和最后交易日期。
- 展示年报、一季报、中报、三季报集中披露窗口。
- 展示股指期货/期权第三个周五和 ETF 期权第四个周三的观察日期。
- 制度推算日期必须标记“规则推算待确认”，节假日和合约调整以交易所正式日历为准。
- 公开信息明确日期标记“公开来源已确认”。
- 所有未来事项在结果发生前 `score_included=false`，不预判利好或利空，只提高刷新频率、降低自动交易权限或要求人工确认。
